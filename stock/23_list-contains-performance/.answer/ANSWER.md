## ❌ NGポイント (bad/ 配下)

1. **既存会員IDを `List` で持ち、申込者ごとに List をなめて探している（＝O(n×m) の二重ループ）**: 申込者1人ごとに `existingMemberIds` を先頭から順に全部見て一致を探している。`List` の中を順番に探す処理は、要素が n 件あれば最悪 n 回の比較が必要（＝計算量 O(n)：件数に比例して遅くなる、という意味。ビッグオーとは「件数が増えたとき処理時間がどう伸びるか」の目安）。これを申込者 m 人ぶん繰り返すので、全体では n×m 回（＝O(n×m)、両方が数万なら実質 O(n²)）の比較が走る。たとえるなら「名簿から1人探すのに毎回1ページ目からめくる」のを申込者の数だけ繰り返す状態で、会員10万・申込10万なら100億回の比較になり、体感で固まる。探す側を `HashSet`（＝ハッシュで一発引きできる集合）にすれば、1件の存在チェックは実質1回（＝O(1)：件数が増えても速さが変わらない）で済み、全体も O(n+m) に激減する。

2. **既存への重複除去も List を毎回なめている（もう一つの隠れた二重ループ）**: 既存と判定するたびに `existingApplicants` を最初から最後まで見て「もう入っているか」を確認している。これも List 探索なので、既存が増えるほど1件あたりの確認が重くなり、ここだけでさらに O(件数²) を上乗せしている。重複判定は「見たIDを `Set` に覚えておいて add の戻り値で判定」すれば O(1) で済む。

3. **無駄な冗長コードとマイクロな非効率**: `if (found == true)` / `if (already == false)` は `if (found)` / `if (!already)` で足りる（`== true` はプロは書かない）。また内側の重複チェックで一致を見つけても `break` せず最後までなめ続けており、途中で抜ければよいところを毎回全走査している。細かいが「無駄な仕事を減らす」意識が薄いサイン。

4. **null チェック漏れ**: `existingMemberIds` や `applicants` が null で渡ると、ループに入った瞬間に `NullPointerException`（＝中身が空っぽの箱を開けようとして落ちるエラー）になる。しかも「どの引数が null だったか」は例外メッセージから読み取りにくい。入口で「必須です」と意味のある例外を投げておけば、原因が一目で分かる。

5. **突合キーの正規化を考慮していない（ID が数値なので今回は軽微だが観点として）**: 今回は会員IDが数値なので影響は小さいが、もし突合キーがメールアドレスや会員コードのような**文字列**だった場合、`"a@example.com"` と `"A@example.com "`（大文字・前後の空白）を別物として扱ってしまい、本来「既存」の人を「新規」に取りこぼす。文字列キーで突合するときは `trim()`（前後の空白除去）＋大文字小文字そろえ、の正規化をしてから Set に入れるのが定石、という点は覚えておきたい。

## ⭕️ 改善案 (good/ 配下)

1. **探される側を最初に `HashSet` に入れて O(1) の存在判定にする**: `Set<Long> existingIdSet = new HashSet<>(existingMemberIds);` の1行で、以降の `contains` が実質1回引きになる。全体の計算量が O(n×m) から O(n+m) に変わり、件数が増えても速度が落ちにくくなる。

2. **重複除去も `Set` の add の戻り値で判定する**: `seenExistingIds.add(memberId)` は「新しく追加できたら true」を返すので、これが true のときだけ結果リストに足せば、List をなめずに重複を弾ける。

3. **冗長な `== true` / `== false` をやめ、早期に抜ける**: `if (found)` のように素直に書き、探索は Set 化で消えるので `break` の有無を気にする箇所自体が無くなる。読みやすさと速さの両取り。

4. **入口で null を弾き、意味のある例外を投げる**: 何が欠けていたか分かるメッセージで `IllegalArgumentException` を投げ、後工程での謎の NPE を防ぐ。

5. **（文字列キーの場合）正規化してから Set に入れる**: 突合キーが文字列なら `key.trim().toLowerCase()` などでそろえてから Set 化・比較する、と設計に織り込む。
