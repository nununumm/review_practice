## ❌ NGポイント (bad/ 配下)

1. **try-with-resources を使わず、`Connection`/`Statement`/`ResultSet` を閉じ忘れる（リソースリーク・最重要）**: `updateName` では開いた `Connection`/`PreparedStatement` を `finally` すら書かずに放置している。例外が起きても起きなくても閉じられないので、接続が「借りっぱなし」になる。接続はコネクションプール（＝接続の使い回しの池）から借りるが、返さないと在庫が尽きて、やがて誰も接続を取れなくなる（＝リソースリーク／接続枯渇）。本番でジワジワ効いてきて、ある日突然DBに繋がらなくなる怖いタイプ。閉じ忘れを人力で管理するのは無理があり、`try (...) {}` に開くもの（＝`AutoCloseable`なもの）を書けば、ブロックを抜けるとき自動で・逆順で・確実に閉じてくれる。

2. **`finally` の `close()` 自体が例外を投げると、本来の例外が握りつぶされる**: `findById` は `finally` の中で `rs.close(); ps.close(); conn.close();` を素直に並べている。もし `rs.close()` が例外を投げると、その場で `finally` から例外が飛び出し、(a)`ps`と`conn`が閉じられない、(b)本来 `try` で起きていた「本当に伝えたかった元の例外」が、この close の例外に上書きされて消える。原因調査のときに「本当の原因」が見えなくなる、地味だが厄介な罠。加えて `NullPointerException` の危険もある：接続取得の前に例外が出ると `rs` が `null` のまま `rs.close()` を呼んで落ちる。try-with-resources なら閉じるときの例外は「抑制例外（suppressed）」として脇に記録され、元の例外がちゃんと主役のまま伝わる。

3. **`catch (Exception e)` で `printStackTrace()` して `return null`（例外の握りつぶし）**: 失敗したのに、コンソールにスタックトレースを吐くだけで `null` を返して「なかったこと」にしている。呼び出し側は「本当に居ないユーザー（正常）」なのか「DBが落ちていた（異常）」なのか区別できない。しかも `catch (Exception e)` は、想定外の `RuntimeException`（バグ）まで一緒に飲み込んでしまう。失敗は意味のある例外に翻訳して呼び出し側へ伝える（＝伝播させる）のが原則。

4. **`Connection` をメソッド内で `DriverManager` から都度取得（DataSource／DI不使用）**: 接続URL・ユーザー名・パスワードをコード内にベタ書きし、`DriverManager.getConnection(...)` で毎回ゼロから接続を作っている。これだと(a)コネクションプールが使えず接続の生成・破棄が毎回発生して遅い、(b)接続情報がソースに埋め込まれて環境ごとに変えられず、パスワード流出のリスクもある、(c)`new` で自前調達しているのでテスト時に偽物の接続へ差し替えられない（＝テストしづらい）。接続は `DataSource`（＝接続の貸し出し窓口）を「注入（DI）」してもらい、そこから借りるべき。

5. **`SELECT *` と `rs.getString(1)` の列番号マジックインデックス**: `SELECT *`（＝全列を取る）＋ `rs.getLong(1)`/`getString(2)` のように「何番目の列か」で結果を読んでいる。この番号は「SELECTした列の並び順」に依存するので、テーブルに列を1つ追加したり順番を変えたりしただけで、`name` のつもりが `email` を読む、といった静かなバグになる（エラーも出ずに値がズレる）。必要な列だけを名前で `SELECT` し、`rs.getString("name")` のように列名で取り出せば、順番が変わっても壊れない。

> 補足（おまけで気づけたら100点）: `bad` は SQL を文字列連結で組み立てている（`"... WHERE id = " + id`、`"... name = '" + name + "'"`）。これは **SQLインジェクション**（＝入力に細工したSQLを混ぜ込まれ、DBを乗っ取られる攻撃）の穴。`PreparedStatement` の「?」プレースホルダで値を渡せば、値はあくまで「データ」として扱われ、SQLとして解釈されないので防げる。`good` はすべて「?」で渡している。

## ⭕️ 改善案 (good/ 配下)

1. **try-with-resources で確実にクローズ**: `try (Connection conn = ...; PreparedStatement ps = ...) { try (ResultSet rs = ...) { ... } }` の形にする。開いたものは抜けるとき自動で閉じられ、`finally` の後始末コードそのものが不要になる。閉じ忘れも、close時の例外による元例外の上書きも、まとめて解消する。

2. **`DataSource` を注入（DI）**: `DriverManager` をやめ、コンストラクタで `DataSource` を受け取る（`private final DataSource dataSource;`）。接続はプールから借りて返す形になり、接続情報はソースから消え、テスト時は偽物を差し込める。

3. **例外は意味のある独自例外に翻訳して伝播**: `SQLException` を握りつぶさず、`DataAccessException`（独自例外）に包んで投げる。このとき原因の `e` を `cause` として渡し、元のスタックトレースを失わない。「0件」と「DB障害」がはっきり区別できるようになる。

4. **列は名前で指定・必要な列だけ SELECT**: `SELECT id, name, email ...` と明示し、`rs.getString("name")` と列名で取り出す。列順の変更に強くなる。行→オブジェクトの詰め替えは `mapRow` に切り出して読みやすくする。

5. **値は「?」プレースホルダで渡す**: 文字列連結をやめ `WHERE id = ?` / `SET name = ?` にして `ps.setLong`/`ps.setString` で入れる。SQLインジェクションを防ぐ。

6. **本命は `JdbcTemplate`**: `JdbcTemplate`（＝Springが接続の開閉・close・後始末を全部肩代わりしてくれる道具）を使えば、`queryForObject` と `update` だけで書け、リソース管理を自分で書く必要がなくなる（`good/UserDaoJdbcTemplate.java`）。実務ではまずこれを選ぶ。素のJDBC版は「中で何が起きているか」を理解するための土台。

## 💬 レビューコメント例文

> UserDao、検索と更新がちゃんと動いていて、`PreparedStatement` を使おうとしている姿勢もいいですね！ そのうえで、ここは「本番で効いてくる」ポイントが詰まっている場所なので、一緒に固めておきましょう。
>
> 一番大事なのがリソースの後始末です。`updateName` は接続やステートメントを閉じていなくて、`findById` も `finally` で閉じてはいるものの、`rs.close()` が失敗すると後続が閉じられず、しかも本当に見たい元の例外が上書きされて消えちゃうんです。ここは `try (Connection conn = ...; PreparedStatement ps = ...) { ... }` の **try-with-resources** に置き換えると、開いたものが自動で・確実に閉じられて、`finally` ごと消せます。接続の借りっぱなし（枯渇）を根本から防げます。
>
> それと接続の取り方も見直したいです。いま `DriverManager` でURLとパスワードをベタ書きして毎回作っていますが、`DataSource` をコンストラクタで注入してもらう形にすると、プールから借りて返せるので速くて安全、テストでも差し替えやすくなります。例外は `printStackTrace` + `return null` だと「居ない」のか「DBが落ちた」のか呼び出し側が区別できないので、意味のある例外（`DataAccessException` など）に包んで投げて、原因の例外も `cause` で渡してあげてください。
>
> 最後に地味だけど大事なのが、`SELECT *` + `rs.getString(1)` の列番号読みと、SQLの文字列連結です。前者は列を1つ足しただけで値がズレる静かなバグ、後者はSQLインジェクションの穴になります。必要な列だけ名前でSELECTして `rs.getString("name")` で取り、値は全部「?」で渡す形にしましょう。……と、直しどころは多いですが、実は `JdbcTemplate` を使うとこの後始末の大半が自動になります。まずは素のJDBCで「何を自分でやっていたか」を体で覚えて、実務では `JdbcTemplate` に寄せていく、の順で行きましょう！
