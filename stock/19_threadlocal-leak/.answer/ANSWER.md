## ❌ NGポイント (bad/ 配下)

1. **`ThreadLocal` を `remove()` で片付けていない（最重要・セキュリティ／情報漏洩）**: `TenantFilter` は処理の最後に `TenantContext.setTenantId(null)` しているだけで、`ThreadLocal`（＝スレッドごとの保管箱）そのものを空にする `remove()` を呼んでいない。Webサーバはスレッドを毎回作り直さず**使い回す**（＝スレッドプール。作業員を数人常駐させ、次々にリクエストを担当させる仕組み）。`set(null)` は「保管箱に null という値を入れた」だけで、保管箱のエントリ自体は残る。もし入口の `if (header != null)` を通らなかった次のリクエストが同じスレッドに割り当たると、前のリクエストが入れた値が残ったまま参照され、**A社の画面にB社のデータが見える**という致命的な情報漏洩・データ混線が起きうる。さらに `ThreadLocal` にエントリが残り続けることで**メモリリーク**（＝使い終わったのに解放されないメモリ）の温床にもなる。正解は `remove()`。

2. **例外が起きると片付けが実行されない（例外処理）**: `chain.doFilter(...)` の後ろに片付けを置いているだけなので、後続処理の途中で例外が飛ぶとその行に到達せず、保管箱が片付かないまま次のリクエストへ引き継がれる。「正常系でだけ片付ける」は片付けたことにならない。**入口でセットしたら `try { ... } finally { clear(); }` で、正常でも異常でも必ず片付ける**のが鉄則。

3. **`static` な可変グローバル状態に暗黙依存していてテストしにくい（設計／テスト容易性）**: `ReportService` が `TenantContext.getTenantId()` を直接呼んでおり、「このメソッドは裏でグローバルなスレッド保管箱を覗いている」ことがシグネチャ（＝メソッドの見た目）から一切わからない（＝隠れた結合）。テストのたびに事前に `ThreadLocal` を仕込む必要があり、仕込み忘れると別テストの残り値で結果が変わる。**引数でテナントIDを明示的に渡せば**、どこから来た値かが一目でわかり、テストでも好きな値を渡すだけで済む。

4. **別スレッドでは `ThreadLocal` が引き継がれず、null を黙って「全テナント対象」にしている（セキュリティ／危険な既定動作）**: `generateMonthlyReports` は `executor.submit(...)` で**別スレッド**に集計を投げているが、`ThreadLocal` は呼び出し元スレッドの値を別スレッドへ引き継がない。そのため別スレッド内の `TenantContext.getTenantId()` は `null` になる。そして `generateReport` の `if (tenantId == null)` は、テナント不明のときに**黙って全テナントのデータを集計して返す**。これは「不明なら安全側に倒す」の真逆で、事故があっても気づけず全社データが漏れる最悪の既定動作。**不明なら例外で止める**べきで、別スレッドへはテナントIDを値として明示的に渡すべき。

## ⭕️ 改善案 (good/ 配下)

1. **`clear()`（＝`remove()`）を用意し、Filter の `finally` で必ず呼ぶ**: `TenantContext.clear()` は内部で `ThreadLocal.remove()` を実行。`TenantFilter` では `try/finally` で囲み、正常でも例外でも保管箱を空にする。これでスレッド使い回しによるデータ混線とメモリリークを両方防ぐ。

2. **入口（Filter）で入れ、出口（finally）で消すを一元管理**: セットと片付けを全リクエストが必ず通る Filter に集約し、各サービスは片付けを気にしなくてよくする。

3. **テナントIDは引数で明示的に渡す**: `ReportService.generateReport(long tenantId)` のように受け取る。グローバルを覗きに行かないので隠れた結合が消え、テストも値を渡すだけになる。`ThreadLocal` からの取り出しは入口側で1回だけ（`requireTenantId()`）行う。

4. **未設定（null）は黙って全件にせず例外にする**: `TenantContext.requireTenantId()` はテナント未設定なら `IllegalStateException` を投げる。「不明なら全社対象」という危険なフォールバックをやめる。

5. **別スレッドへは値を明示的に伝播する**: `generateMonthlyReports(long tenantId, ...)` で `tenantId` を受け取り、ラムダに閉じ込めて（キャプチャして）各タスクに持たせる。別スレッド内でも渡した値をそのまま使えるので null にならない。あわせて `invokeAll` と割り込み時の `Thread.interrupt()` 復元で、例外・中断を握りつぶさない。
