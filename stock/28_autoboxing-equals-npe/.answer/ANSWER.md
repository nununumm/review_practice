## ❌ NGポイント (bad/ 配下)

1. **`Integer` どうしを `==` で比較している（ある日突然バグる時限爆弾）**: `return rankId == targetRankId;` は、`Integer`（＝オブジェクト版の整数）どうしを `==` で比べている。`==` は「値が同じか」ではなく「同じオブジェクト（実体）を指しているか」を見る比較（＝参照比較）。ここが厄介なのは、Java が `-128〜127` の `Integer` だけを内部でキャッシュ（作り置き）して使い回すため、その範囲では同じ値だと偶然 `true` になってしまうこと。テストでランクID を 1 や 5 で試すと通ってしまうので、レビューでも見逃されやすい。ところが本番でランクID が `128` 以上になった瞬間、キャッシュされない＝別オブジェクトになり、値が同じでも `false` になる。「今まで動いていたのに、ある日から特定のランクだけ判定がおかしい」という、原因の特定が非常に難しいバグになる。値の比較は `.equals()`（または `Objects.equals`）を使うか、プリミティブ `int` に直してから `==` する。たとえるなら、`==` は「同じ人か（本人確認）」を、`.equals()` は「同じ名前か（中身が同じか）」を見るようなもので、値を比べたいのに本人確認をしてしまっている。

2. **null になりうる `Long` を `int` に受けて、アンボクシングで NPE**: `int total = repository.sumPoints(memberId);` の `sumPoints` は、DBの `SUM()` を呼んでいる想定。`SUM()` は対象が0件のとき合計 `0` ではなく `null`（該当なし）を返すのが SQL の仕様。その `null` を `int`（プリミティブ）に代入しようとすると、ラッパー型からプリミティブ型への自動変換（＝アンボクシング：箱から中身を取り出す変換）の途中で「中身が無い（null）」ため `NullPointerException` で落ちる。ポイントを1件も持たない新規会員でいきなり落ちる、という地味だが致命的なバグ。`Long` のまま受けて、`null` なら `0` とみなしてから比較すべき。

3. **`Boolean flag` を `if (flag)` でそのまま使い、null だと NPE**: `Boolean flag = repository.findPremiumFlag(memberId);` の戻り値は `Boolean`（＝オブジェクト版の真偽値）で、DBのカラムが未設定なら `null` になりうる。これを `if (flag)` と書くと、`if` は `boolean`（プリミティブ）を必要とするため、ここでもアンボクシングが起き、`flag` が `null` だと `NullPointerException` で落ちる。`Boolean.TRUE.equals(flag)` のように書けば、`null` でも安全に `false` として扱える。（なお `if (flag) return true; else return false;` という書き方自体も冗長で、`return 判定式;` にできる。）

4. **しきい値のマジックナンバーと、フィールドインジェクション**: しきい値 `1000` が裸の即値（＝マジックナンバー：それ単体では何の数字か分からない値）で埋め込まれており、意味も分からず変更箇所も探しにくい。また依存を `@Autowired private ... repository;`（＝フィールドインジェクション）で受けており、テスト時に差し替えづらい・不変にできない、という設計上の弱さもある。定数化とコンストラクタインジェクションにすべき。

## ⭕️ 改善案 (good/ 配下)

1. **値の比較は `Objects.equals(...)` かプリミティブ化する**: `Integer` どうしの `==` をやめ、`Objects.equals(rankId, targetRankId)` で値を比較する。これなら 128 以上でも正しく判定でき、両方 `null` でも安全。

2. **null になりうる集計は `Long` で受け、null を 0 とみなす**: `Long total = repository.sumPoints(memberId);` と受けてから、`null` なら `0L` に置き換えて比較する。0件会員でも落ちない。

3. **`Boolean` は `Boolean.TRUE.equals(...)` で安全に判定する**: `if (flag)` を避け、`return Boolean.TRUE.equals(flag);` と書く。`null` は自動的に `false` 扱いになり、`return 判定式;` で冗長な if も消える。

4. **しきい値を定数化し、コンストラクタインジェクションにする**: `POINT_THRESHOLD` を `static final` で定義して意味を与え、依存はコンストラクタで受け取ってテスト時に差し替えやすくする。
