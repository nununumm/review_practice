## ❌ NGポイント (bad/ 配下)

1. **`instance` フィールドに `volatile` が無く、ダブルチェックロッキングが壊れている（核心）**: `synchronized` の外側で `if (instance == null)` を見て、中でもう一度見る——という「ダブルチェックロッキング」を手書きしているが、この形は `instance` が `volatile`（＝すべてのスレッドから常に最新の値が見える／命令の並べ替えを禁じる印）でないと**正しく動かない**ことが知られている。`instance = new ExchangeRateHolder();` は、CPU/JVM から見ると「①置き場所を確保 → ②コンストラクタで中身を組み立て → ③ instance に代入」の3手順で、高速化のため②と③が入れ替わりうる。すると「instance には入ったが中身は未完成」という一瞬が生まれ、別スレッドが synchronized の外側チェックでその**中身が空のオブジェクト**を掴んで返してしまう。再現しづらく、本番の高負荷時にだけ起きるたちの悪いバグ。

2. **そもそも手書きのダブルチェックロッキングは避けるべき（設計）**: 上記のように正しく書くのが難しく、レビューでも見落とされやすい。Java には「初期化オンデマンド・ホルダー（static holder）」という、JVM のクラス初期化がスレッドセーフに1回だけ走る保証を利用したイディオムがあり、`volatile` も `synchronized` も自分で書かずに「遅延初期化＋スレッド安全」を両立できる。手書きロックより安全で読みやすい。

3. **`rateTable` が `final` でなく可変で、部分構築オブジェクトの漏洩を助長している**: `rateTable` は生成時に一度だけ作れば十分な値なのに `final` になっておらず、あとから差し替え可能。NG 1 と相まって「未初期化状態が見える」危険を広げている。

4. **`getRateTable()` が内部のレート表参照をそのまま返している（防御的コピー欠如／低）**: 共有シングルトンが持つ可変な `RateTable` の参照を外に渡すと、ある呼び出し側が中身を書き換えたとき全スレッドに影響する。読み取り専用ビューを返す等の配慮が要る。

## ⭕️ 改善案 (good/ 配下)

1. **「初期化オンデマンド・ホルダー」イディオムに置き換える**: `private static class Holder { static final INSTANCE = new ...; }` を用意し、`getInstance()` で `Holder.INSTANCE` を返す。`Holder` は初めて参照された瞬間に JVM が1回だけ・スレッドセーフに初期化するため、遅延初期化と安全性を同時に満たせる。`volatile`/`synchronized` を手書きしなくてよい。

2. **どうしても DCL を使うなら `private static volatile` にする**: 手書きにこだわる場合でも `volatile` は必須。ただし上のホルダー方式のほうが素直。

3. **一度だけ決まる値は `final` にする**: `rateTable` を `final` にして「作った後は差し替えない」ことをコンパイラに保証させる。

4. **可変な内部状態を直接返さない**: `getRateTable()` は不変ビュー or 防御的コピーを返すことを検討する。

## 💬 レビューコメント例文

> 重い初期化を「必要になったとき1回だけ」にしたい、という狙いは正しいですし、ダブルチェックロッキングを知っているのも good です。ただ、この形には有名な落とし穴があって、`instance` を `volatile` にしないと壊れるんです。`instance = new ...()` は内部的に「箱を確保 → 中身を組み立て → 変数に代入」の順ですが、JVM は速度のため代入を先にやってよくて、その一瞬「変数には入ったけど中身は空」の状態を別スレッドが synchronized の外側チェックで拾ってしまうと、未完成のオブジェクトを掴みます。しかも高負荷時にしか出ないので、デバッグが本当に大変なタイプです。

> おすすめは、手書きロックをやめて「初期化オンデマンド・ホルダー」に置き換えることです。`private static class Holder { static final ExchangeRateHolder INSTANCE = new ExchangeRateHolder(); }` を作って、`getInstance()` は `Holder.INSTANCE` を返すだけ。クラスの初期化は JVM がスレッドセーフに1回だけやると保証しているので、`volatile` も `synchronized` も書かずに遅延初期化と安全性を両取りできます。読みやすさも段違いですよ。ついでに `rateTable` は `final` にして、`getRateTable()` は中身を直接返さないようにしておくと、共有インスタンスとしてより安心です。
