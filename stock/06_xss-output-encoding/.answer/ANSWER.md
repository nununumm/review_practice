## ❌ NGポイント (bad/ 配下)

1. **格納型XSS（保存された悪意スクリプトが他人のブラウザで動く）**:
   投稿された `author` / `body` を、何も加工せずそのまま HTML に埋め込んで返しています。
   攻撃者が本文に `<script>...</script>` や `<img src=x onerror=...>` を投稿すると、
   その文字列がDBに保存され、**記事を見にきた別の閲覧者全員のブラウザでスクリプトが実行**されます。
   （＝XSS。特に「保存されて後から何度も発火する」ので格納型と呼び、被害範囲が広い）
   Cookie（ログイン情報）を盗まれたり、勝手に投稿・操作させられたりします。
   「入口の1人が仕込むと、後から来る全員がやられる」時限爆弾のようなものです。

2. **HTMLを文字列連結で手組みしている**:
   `"<div>" + userInput + "</div>"` のように、自分で `+` を使ってHTMLを組み立てています。
   この方式だと「エスケープ（＝ `<` を `&lt;` のような無害な文字に変換すること）」を
   1か所ずつ手で書くしかなく、**必ずどこかで書き忘れて穴になります**。
   テンプレートエンジンの「自動エスケープ」という安全網を自ら捨てている状態です。

3. **オープンリダイレクト（外部サイトへ勝手に飛ばされる）**:
   投稿後、ユーザーから受け取った `returnUrl` をそのまま `RedirectView` に渡しています。
   `returnUrl=https://evil.example` のように細工されると、
   自サイトのURLからワンクリックで**攻撃者の偽サイトへ誘導**できてしまいます
   （フィッシングに悪用される。＝オープンリダイレクト）。

4. **入力の検証が一切ない**:
   本文・投稿者名の**長さ制限も、許可文字のチェックもありません**。
   数十万文字の巨大投稿でページやDBを荒らされたり、記号を悪用した攻撃を素通ししたりします。

5. **出力コンテキストの区別がない**:
   同じ `author` を「タグの中身（`<span>author</span>`）」と「属性値（`title='author'`）」の
   両方に入れています。実は**必要なエスケープは場所ごとに違います**
   （HTML本文用・HTML属性用・URL用でルールが別）。
   属性値に `'` を仕込まれると属性を抜け出して別の属性（`onmouseover=` 等）を注入できます。
   「どこに出すか」を意識しない手組みは、この違いを取りこぼします。

## ⭕️ 改善案 (good/ 配下)

1. **出力時にエスケープする（XSS対策の基本方針）**:
   XSSは「入力時に危険文字を消す」より「**表示する瞬間にエスケープする**」のが定石です。
   good版では Thymeleaf テンプレートの `th:text` を使い、`<script>` を投稿されても
   画面には `&lt;script&gt;`（ただの文字）として表示され、スクリプトは動きません。
   `@Controller` + テンプレートに切り替え、HTMLの手組みをやめました。
   （REST APIでどうしても文字列を返すなら
   `org.springframework.web.util.HtmlUtils.htmlEscape(...)` で1つ1つ包む手もあります）。

2. **出力先ごとにエスケープを使い分ける**:
   タグの中身は `th:text`、属性値は `th:attr`（属性用エスケープが自動で効く）を使い、
   「本文・属性・URL でエスケープが違う」という考え方をテンプレートに任せます。

3. **リダイレクト先はサーバー側で組み立てる**:
   `returnUrl` をそのまま使わず、`"redirect:/articles/" + articleId` のように
   **サーバー側で安全なURLを作ります**。オープンリダイレクトを根本から断てます。
   どうしても遷移先を可変にしたい場合は `SafeRedirect` のように
   「自サイト内の相対パスだけ許可（`//host` や `http://` は拒否）」する許可リスト方式にします。

4. **入力を検証する**:
   `CommentForm`（入力専用のDTO）に `@Size`（長さ）・`@Pattern`（許可文字）・`@NotBlank` を付け、
   `@Valid` で自動チェック。Entityを直接入力受けにせず、外から来る値を安全に受け止めます。

5. **役割を分ける**:
   保存処理は `@Service`（CommentService）に寄せ、Controllerは入口の交通整理に専念。
   テストしやすく、責務が読みやすくなります。
