## ❌ NGポイント (bad/ 配下)

1. **`break` 忘れによるフォールスルー（＝突き抜け）でプラチナが半額になる**:
   従来型の `switch` は、`case` の処理の最後に `break` を書かないと、そこで止まらず**次の `case` の処理まで続けて実行**されてしまう。これを「フォールスルー（＝突き抜け）」と呼ぶ。
   bad のコードは `case "PLATINUM": fee = 0;` の後に `break` が無い。そのため `fee = 0`（無料）にした直後、そのまま隣の `case "GOLD": fee = baseFee / 2;` まで実行され、**プラチナ会員が「半額」に上書き**されてしまう。仕様は「プラチナは送料無料」なのに、実際は半額を請求する重大なバグ。
   さらにタチが悪いのは、これは**文法的には正しいのでコンパイルが通ってしまう**こと。エラーで教えてくれないので、実際に動かして「あれ、プラチナなのに送料取られてる」と気付くまで見逃されやすい。

2. **`default` が無く、想定外のランクが「無言」で素通りする**:
   `switch` に `default`（＝どの `case` にも当てはまらなかったときの受け皿）が無い。だから "BRONZE" や誤記の "GLOD" のような想定外の値が来ると、**どの `case` にも入らず `fee` は初期値 0 のまま**返ってしまう。
   本来なら「知らないランクが来た」と気付いて対処すべき場面なのに、何のエラーも出ず送料0で通ってしまう。こういう「静かなバグ（＝誰も気付かないまま間違った結果を出し続ける）」が一番怖い。**想定外はあいまいに握りつぶさず、例外を投げて即座に気付けるようにする**のが鉄則。

3. **ランクを文字列（マジック値）で扱っていて網羅性を保証できない**:
   ランクを `"PLATINUM"` のような**ただの文字列**で判定している。文字列はタイプミスしても（"GLOD" など）コンパイラが気付いてくれないし、「全ランクを漏れなく扱えているか（＝網羅性）」も保証されない。本来はランクを **enum（＝取りうる値をあらかじめ列挙した専用の型）** にすべき。そうすればタイプミスはコンパイル時に弾け、分岐の抜けも見つけやすくなる。

4. **そもそも従来型 `switch` は `break` の付け忘れが起きやすい危険な構文**:
   従来型 `switch` は「毎回 `break` を書くのを人間が覚えておく」前提の構文で、1つでも書き忘れると1番のような事故になる。人の注意力に頼る書き方は、いつか必ず抜ける。構文レベルで事故が起きない書き方に変えるのが根本対策。

## ⭕️ 改善案 (good/ 配下)

1. **アロー構文の `switch 式` に置き換え、フォールスルーを構文的に不可能にする**:
   Java 14 以降で使える **`switch 式`（＝各分岐が値を直接返す新しい書き方。`break` が不要）** を使う。
   `case "PLATINUM" -> 0;` のように書くと、その分岐は右側の値を返すだけで、**隣の `case` へ突き抜けることが構文上あり得ない**。`break` を書き忘れる余地そのものが無くなる。しかも `return switch (...) { ... };` で計算結果をそのまま返せるので、`fee` という一時変数も要らず短く読みやすい。

2. **`default` で例外を投げ、想定外を握りつぶさない**:
   `default -> throw new IllegalArgumentException("未知の会員ランク: " + rank);` とする。想定外のランクが来たら送料0で静かに通すのではなく、**「知らないランクが来た」とはっきり例外で知らせて処理を止める**。バグの発見が早くなり、原因も（メッセージにランク名を入れてあるので）すぐ分かる。

3. **（発展）ランクは enum にするのが本来の姿**:
   今回は switch の安全化に集中したので String のままだが、コメントで触れたとおり、本来はランクを enum にするとタイプミスをコンパイル時に弾け、網羅性も保証しやすい。

## 💬 レビューコメント例文

> ランクごとの送料を1メソッドにまとめてくれていて、仕様（プラチナ無料・ゴールド半額…）も追いやすいですね。ここまでの整理、いいと思います。
>
> ひとつ大事な点として、`switch` の `case "PLATINUM"` に `break` が無くて、そのまま `GOLD` の処理まで突き抜けてしまっています（フォールスルーと言います）。このままだと送料無料のはずのプラチナ会員が半額請求になってしまう不具合で、しかもコンパイルは通ってしまうので気付きにくいんです。あと `default` が無いので、"BRONZE" や打ち間違いのランクが来たときに送料0のまま静かに通ってしまうのも怖いところ。想定外はあえて例外で落として、すぐ気付けるようにしておきたいです。
>
> おすすめは `case "PLATINUM" -> 0;` のようなアロー構文の switch 式への置き換えです。値を直接返せて `break` 自体が要らなくなるので、突き抜け事故が構文レベルで起きなくなります。`default` で `IllegalArgumentException` を投げるところまで入れれば安心。慣れてきたらランクを enum にする話もまたやりましょう。ここが直せると一気に堅牢になりますよ！
