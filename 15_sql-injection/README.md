# 第15問：商品検索サービス

**📅 出題日**: 2026年8月1日

## 📋 レビュー課題

ECサイトの「商品検索」機能です。検索画面から **キーワード（商品名のあいまい検索）**・**カテゴリ**・**並び順（ソートするカラム）** の3つを受け取り、条件に合う商品の一覧を返します。DB からデータを取得して `List<Product>` を組み立てる、ごく普通の検索処理に見えます。

対象: `bad/ProductSearchService.java`

一見ちゃんと動きますが、**チーム開発に出すと事故になる問題**が潜んでいます。
「どこが問題か、どう直すべきか」をテックリード目線でレビューしてみてください。

---

## ❌ NGポイント (bad/ 配下)

1. **SQLインジェクション（keyword / category）**: ユーザー入力を `"... LIKE '%" + keyword + "%'"` のように文字列連結でSQLに埋め込んでいる。`' OR '1'='1` のような入力で**SQL文の意味を書き換えられ、全件漏洩・データ破壊**につながる。最も重大なセキュリティ欠陥。
2. **SQLインジェクション（ORDER BY sortColumn）**: `sortColumn` も直結している。プレースホルダー（`?`）は**「値」にしか使えず「列名・並び順」には使えない**ため、ここは別の守り方（許可リスト）が必要。放置すると2つ目の注入口になる。
3. **リソースリーク**: `Connection` / `Statement` / `ResultSet` を開くだけで `close()` していない。検索のたびにDB接続が返却されず溜まり、**接続枯渇でシステム全体が停止**する。
4. **例外の握りつぶし**: `catch (Exception e)` で捕まえて空リストを返している。DB障害などの失敗が**「検索成功（0件）」に化ける**ため、呼び出し側が異常に気づけない。
5. **貧弱なエラー出力**: `System.out.println` はログ基盤に乗らず、レベル分けもできない。さらに `e.getMessage()` だけでは**スタックトレース（どこで壊れたか）が失われ**、原因調査が困難。
6. **生JDBCの手組み**: Spring では `JdbcTemplate` を使えば、安全なパラメータ化・リソースの後片付け・例外変換をまとめて任せられる。手組みは車輪の再発明で、上記のバグを生みやすい。

## ⭕️ 改善案 (good/ 配下)

1. **値はすべてプレースホルダー（`?`）＋バインド変数**にする。`keyword` / `category` は連結せず、値は引数リストで渡す（あいまい検索の `%` は「値」の側に付ける）。
2. **`ORDER BY` は許可リスト（ホワイトリスト）で検証**してから連結する。あらかじめ許可した列名以外は既定値（`id`）に倒し、危険な入力は無視する。
3. **`JdbcTemplate` を採用**。内部で `PreparedStatement` を使うため安全で、接続や `ResultSet` の後片付けも自動化され、**リソースリークを構造的に防げる**。
4. **握りつぶさない**。失敗時は独自例外 `ProductSearchException` に包んで上位へ伝播させ、「失敗を成功に見せかけない」。
5. **`Logger` でエラー出力**。例外オブジェクト `e` を丸ごと渡してスタックトレースを残し、検索条件も一緒に記録して調査を速くする。

## 💬 レビューコメント例文

> 検索機能ありがとうございます、動作はOKでした！ 一点だけ、マージ前に直したいところがあります。`keyword` や `category` をSQL文に直接つなげているんですが、ここはユーザーが入力した文字がそのままSQLの命令として解釈されてしまう「SQLインジェクション」の入口になり得ます。値の部分は `?`（プレースホルダー）にして `JdbcTemplate` に値を渡す形にすると、この攻撃を原理的に防げます。
>
> `ORDER BY` の列名だけは `?` が使えない（プレースホルダーは値専用で列名には効かない）ので、そこは「許可する列名の一覧」を用意して、その中にある時だけ使う形にしましょう。
>
> あわせて、`Connection` まわりが `close()` されていないのでリークが心配です。`JdbcTemplate` に寄せると後片付けも自動になるので、そこも一緒に巻き取れます。エラー時は `println` ではなく logger で例外ごと出す＆握りつぶさず例外を投げる、にしておくと運用が楽になります。一緒に直しちゃいましょう！
